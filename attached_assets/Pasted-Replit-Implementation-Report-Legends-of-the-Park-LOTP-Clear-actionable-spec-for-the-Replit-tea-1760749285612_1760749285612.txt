3) High-level architecture & recommended tech (Replit-friendly)
	•	Frontend: React (Vite) or Next.js (recommended: Next.js with Static Export / ISR)
	•	Why Next.js: static export (ideal for low-cost hosting), ISR for rare dynamic pages, good image optimization, built-in routing.
	•	If simplest: React + Vite with static export and client-side router (React Router).
	•	Backend: Supabase for auth, storage, and Postgres DB (owner already intends Supabase).
	•	Use Supabase client from frontend (RLS) — avoid backend processes running 24/7.
	•	Hosting on Replit: prefer static build output (static site) + serverless functions only for necessary API routes (Replit’s “always-on” repls drive costs).
	•	CDN: Serve static assets via a CDN (Replit static + external CDN if available).
	•	Storage: Supabase Storage for images (avatars, park images). Use optimized sizes + signed URLs.
	•	Analytics: Lightweight (e.g., Plausible or GA4 privacy-lite) or serverless event batching.
	•	Optional: WordPress integration only if explicitly needed; otherwise keep WordPress out to reduce complexity.

⸻

4) Cost & Replit-usage minimization strategy (concrete steps)
	1.	Static-first: Build pages as static where possible (Homepage, Parks Index, Park pages pre-rendered). Use serverless only for dynamic actions (signup, auth).
	2.	Disable long-running dev servers in production: Ensure Replit’s project does not auto-run watchers in production. Use build output and serve static files.
	3.	No persistent background workers: Avoid any always-running processes (cron, socket servers). If scheduled jobs needed, run externally (e.g., Supabase Edge Functions or a cheap scheduler).
	4.	Client-side Supabase: Use the Supabase JS client in the browser for auth and data reads/writes to avoid a middle server process.
	5.	Batching & Debounce: Batch write operations and debounce user events (e.g., profile updates) to reduce API calls.
	6.	Image optimization:
	•	Generate multiple sizes, use <img srcset> or Next/Image optimization.
	•	Lazy load offscreen avatars and park images; only load high res for the center park image.
	•	Limit avatar upload size/resolution client-side.
	7.	Cache aggressively: Use browser caching + CDN TTLs for static content.
	8.	Limit Dev Hot Reload: Developers should turn off hot reload or run builds locally when not actively developing to avoid cost.
	9.	Feature flags for agent/AI: Any agent integrations should be optional and disabled by default. Don’t allow an AI/agent to run automatically in the user’s Repl.
	10.	Monitoring threshold: Add a simple usage monitor page that displays app metrics so the owner can see if usage spikes.
	11.	Starter dev environment: include a .replit and replit.nix that uses a static run command in production — e.g., serve build rather than vite dev.

13) Developer notes — common pitfalls & fixes
	•	Buttons appear inactive: usually a JS error prevented hydration. Check browser console for exceptions. Ensure client bundle loaded and element class names not mismatched after SSR/SSG.
	•	Homepage renders a park: default route or Link misconfigured. Ensure router index route (/) maps to Home component; check Replit run command isn’t serving a park page index.html.
	•	Bubble gallery overlap / spacing: CSS z-index or absolute positioning miscalculation. Use an algorithm to place avatars on circumference scaled to container size; fallback to grid for mobile.
	•	High Replit usage: dev server running forever or agents enabled. Ensure no node scripts setInterval or open sockets running in production. Use static artifacts.

16) Helpful code snippets (Router & Sidebar example)

Use client-side routing and ensure clicks trigger navigation:

// SidebarButton.jsx (React)
import { useRouter } from 'next/router' // or react-router
export default function SidebarButton({href, label}) {
  const router = useRouter();
  return (
    <button
      onClick={() => router.push(href)}
      aria-label={label}
      className="sidebar-button"
    >
      {label}
    </button>
  );
}

Debug tip: if onClick is firing but nothing navigates — put console.log('click') in handler; if not printed, an overlay or pointer-events CSS is blocking the click.
